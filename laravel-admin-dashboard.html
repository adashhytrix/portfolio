Laravel Admin Dashboard

Role & Permission Management System

A secure and customizable admin dashboard built with Laravel, PHP, MySQL and Bootstrap. Includes role-based access control, admin authentication, user management, and API authentication and authorization functionality.

GitHub Repository Installation Guide

Project Overview

The Laravel Admin Dashboard is designed to manage users, roles, permissions, and administrative operations through a centralized interface.

It implements Role-Based Access Control (RBAC), allowing administrators to control which users can access specific modules and perform particular actions.

Installation & Setup

Follow these simple steps to install and run the project locally.

Step 1: Download the Project

Download the project ZIP from GitHub and extract it, or clone the repository: 

git clone https://github.com/adashhytrix/laravel-admin-dashboard.git

cd laravel-admin-dashboard
Step 2: Install Dependencies

Open the project terminal and run:

composer install
Step 3: Configure Environment

Rename .env.example to .env and configure your MySQL database credentials.

Step 4: Generate Application Key
php artisan key:generate
Step 5: Run Database Migration
php artisan migrate
Step 6: Run Database Seeder
php artisan db:seed

The seeder creates the initial data and administrator account if configured in the project.

Step 7: Start the Laravel Server
php artisan serve
Step 8: Open Admin Login

Open the following URL in your browser:

http://127.0.0.1:8000/admin/login
Admin Credentials:
Please check the AdminSeeder.php file for the configured administrator login credentials. Do not use production credentials in public documentation.

System Requirements

  • PHP version compatible with composer.json
  • Composer
  • MySQL or MariaDB
  • Git
  • XAMPP or another local PHP environment (optional)

Security Recommendations

  • Never publish .env files or database credentials.
  • Validate all incoming requests.
  • Enforce permissions on the server side.
  • Protect privileged roles from unauthorized changes.
  • Use HTTPS in production.
  • Disable debug mode in production.
